# Golden One — Управление устройствами в кредит (Device Financing Lock)

Система для кредитной организации, которая **продаёт iPhone в рассрочку/кредит** и должна
иметь возможность **дистанционно блокировать** устройство при просрочке платежа —
легальным способом, через MDM (Mobile Device Management).

> ⚠️ Ключевой факт по iOS: сторонним приложением заблокировать iPhone **нельзя**.
> Единственный надёжный путь — устройство должно быть **supervised** и заведено в **ваш MDM**
> ещё **на точке продажи**. Тогда доступна команда **Lost Mode** (полная блокировка экрана
> с вашим сообщением и телефоном; экстренные вызовы сохраняются).

---

## 1. Бизнес-контекст и решения

| Параметр | Решение | Почему |
|---|---|---|
| Модель устройства | Организация **продаёт/финансирует** телефоны | Только так iOS-блокировка возможна |
| Что строим | Дашборд + backend с **абстракцией MDM** | Свой MDM-сервер — месяцы работы, не нужен |
| Первый MDM-вендор | **Mosyle** (хороший API, недорого) | За абстракцией — можно сменить |
| Enrollment | **Apple Configurator** на PoS + managed **Activation Lock** | ABM в Узбекистане недоступен напрямую |
| Резервный enrollment | **ADE/DEP** через ABM | Если появится доступ через реселлера |
| Тип блокировки | **Lost Mode** | Стандарт для взыскания, экстренные звонки работают |
| Триггер блокировки | **Вручную** оператором взыскания | Автотриггер по API — фаза 2 |
| Страна | Узбекистан | Определяет путь enrollment |
| Язык интерфейса | Русский + узбекский (i18n) | Аудитория |

## 2. Как это работает физически (жизненный цикл устройства)

```
1. ЗАВЕДЕНИЕ НА ТОЧКЕ ПРОДАЖИ (enrollment)
   ├─ Клиент оформляет рассрочку на iPhone
   ├─ Оператор через Apple Configurator (Mac + кабель):
   │    • стирает и переводит устройство в SUPERVISED
   │    • ставит профиль вашего MDM (без возможности удаления)
   │    • включает managed Activation Lock (телефон нельзя перепродать/сбросить в обход)
   ├─ В дашборде создаётся запись: клиент ↔ устройство (serial/IMEI) ↔ кредитный договор
   └─ Клиент получает разблокированный, полностью рабочий телефон

2. НОРМАЛЬНАЯ ЭКСПЛУАТАЦИЯ
   └─ Устройство «на связи» с MDM; статус — Активно

3. ПРОСРОЧКА
   ├─ Оператор видит просроченные договоры в дашборде
   ├─ Отправляет предупреждение (push/SMS — фаза 2)
   └─ При необходимости жмёт «Заблокировать» → backend → MDM API → EnableLostMode
        • на телефоне: экран блокировки с текстом и номером для оплаты
        • экстренные вызовы работают

4. ОПЛАТА / РАЗБЛОКИРОВКА
   ├─ Клиент оплачивает, оператор жмёт «Разблокировать» → DisableLostMode
   └─ Телефон снова полностью рабочий

5. ПОГАШЕНИЕ КРЕДИТА
   ├─ Договор закрыт → снятие supervision/Activation Lock, удаление MDM-профиля
   └─ Устройство «отпускается» клиенту навсегда
```

### MDM Abstraction Layer — контракт
```ts
interface DeviceManager {
  getEnrollmentStatus(serial: string): Promise<EnrollmentStatus>
  lock(serial: string, opts: { message: string; phone: string }): Promise<CommandResult>  // Lost Mode ON
  unlock(serial: string): Promise<CommandResult>                                           // Lost Mode OFF
  locate(serial: string): Promise<GeoPoint>
  playSound(serial: string): Promise<CommandResult>
  removeManagement(serial: string): Promise<CommandResult>   // при закрытии договора
}
```
Каждый вендор — отдельный адаптер. Дашборд и бизнес-логика ничего не знают о конкретном MDM.

## 4. Модель данных (ядро)

- **Customer** — ФИО, телефон, документ, договоры.
- **LoanContract** — сумма, ежемесячный платёж, оплачено, дата следующего платежа, статус
  (`ACTIVE` / `OVERDUE` / `PAID` / `DEFAULTED`), дней просрочки, дата последнего предупреждения.
- **Payment** — каждое поступление денег: сумма, способ (`CASH`/`CARD`/`TRANSFER`/`OTHER`),
  примечание, кто принял. Договор пересчитывается от этих записей, а не правится вручную.
- **Device** — serial, IMEI, модель, состояние supervision, `enrollmentStatus`,
  `lockStatus` (`UNLOCKED` / `LOCK_PENDING` / `LOCKED` / `UNLOCK_PENDING`), привязка к договору и клиенту.
- **MdmCommand** — очередь команд (`LOCK`/`UNLOCK`/`LOCATE`/`SOUND`), статус доставки
  (`PENDING`/`ACKNOWLEDGED`/`ERROR`), число попыток, ключ идемпотентности.
- **AuditLog** — кто, что, когда, по какому устройству/договору (обязательно для комплаенса).
  Таблица **append-only**: UPDATE и DELETE запрещены триггерами на уровне PostgreSQL.
- **User** — оператор/админ, роль, права, `tokenVersion` для отзыва сессий.

### Два состояния вместо одного

`LOCK_PENDING` и `UNLOCK_PENDING` — не косметика. MDM принимает команду, но телефон применяет её,
только когда выйдет на связь. «Команда отправлена» и «телефон заблокирован» — разные факты, и
оператор, который решает судьбу клиента, должен видеть какой из них перед ним. Фоновый
реконсилятор опрашивает MDM и переводит команду в финальное состояние.

### Сколько платить, чтобы разблокировать

Договор хранит ежемесячный платёж, а API отдаёт вычисляемое поле `arrears` — сумму, которая
закрывает просрочку **сегодня**. Клиент, отставший на три платежа, внеся один, остаётся
просроченным и заблокированным; форма приёма платежа поэтому подставляет `arrears`, а не
месячный платёж, и предупреждает, если оператор вводит меньше.

## 5. Экраны админ-панели (в прототипе)

1. **Дашборд** — KPI: всего устройств, активные договоры, просрочка, заблокировано; лента событий.
2. **Устройства** — таблица: клиент, модель, IMEI, статус договора, статус MDM, статус блокировки; фильтры.
3. **Карточка устройства** — вся информация + действия: **Заблокировать (Lost Mode)** / **Разблокировать** / Найти / Звук / история команд.
4. **Заведение устройства (PoS)** — регистрация нового финансируемого телефона, проверка supervision.
5. **Журнал аудита** — все действия операторов.
6. **Настройки** — подключение MDM (Mosyle), роли, шаблон сообщения блокировки, язык.

Ключевой UX-момент: блокировка — **необратимое для клиента действие**, поэтому подтверждение
с предпросмотром экрана Lost Mode (текст + телефон), причиной и вводом подтверждения.

---

## 6. Роли и права

| Роль | Права |
|---|---|
| **Оператор PoS** | Заводить устройства, видеть свои точки; блокировать — нет |
| **Оператор взыскания** | Видеть просрочку, блокировать/разблокировать, отправлять предупреждения |
| **Администратор** | Всё + настройки MDM, роли, аудит |

Все действия блокировки/разблокировки логируются с указанием оператора и причины.

## 7. Комплаенс и риски

- **Согласие клиента**: блокировка как мера при просрочке должна быть прописана в кредитном
  договоре (оферте). Юридически проверить по законодательству РУз о защите прав потребителей.
- **Экстренные вызовы**: Lost Mode их сохраняет — это важно и должно оставаться всегда.
- **Зависимость от Apple**: supervision снимается при некоторых сценариях восстановления —
  поэтому обязателен **managed Activation Lock**, иначе телефон можно сбросить и перепродать.
- **Проверка ABM**: подтвердить у Apple-реселлера, доступен ли ABM/ADE в Узбекистане; если да —
  enrollment сильно упрощается (без ручного Configurator).
- **Безопасность**: доступ к блокировке — только по ролям, 2FA для операторов, полный аудит.

## 8. Дорожная карта

- **Фаза 0 (сейчас):** план + кликабельный прототип UI (этот репозиторий).
- **Фаза 1 (готово):** backend + БД + MosyleAdapter + ручная блокировка/разблокировка + аудит +
  enrollment + реконсилятор команд + дашборд, подключённый к API.
- **Фаза 2 (готово):** приём платежей и пересчёт графика, автоматическая разблокировка при
  погашении просрочки, политика взыскания (предупреждения по расписанию), автоблокировка —
  **выключена по умолчанию**.
- **Фаза 3:** реальный канал уведомлений (SMS/push вместо лога), интеграция с кредитной системой
  банка, прогрессивные ограничения перед полной блокировкой.
- **Фаза 4:** второй MDM-адаптер, аналитика взыскания, мобильное приложение оператора PoS.

### Почему автоблокировка выключена

`AUTO_LOCK_ENABLED=false` — значение по умолчанию и его нельзя унаследовать случайно. Лишить
человека телефона без решения оператора — шаг с юридическим весом; он должен включаться
осознанно, после того как основание прописано в договоре. Предупреждения при этом работают
всегда: просрочка не должна становиться блокировкой без предупреждения.

## 9. Прототип

`prototype/index.html` — самодостаточный кликабельный прототип (открывается в браузере без сборки).
Тёмная fintech-тема, переключатель RU/UZ, демо-данные, рабочие сценарии блокировки/разблокировки
в памяти. Backend не подключён — это дизайн-макет для согласования.
